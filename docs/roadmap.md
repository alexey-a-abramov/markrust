# MarkRust WYSIWYG Roadmap — status & handoff

_Last updated: 2026-08-30. This is the working roadmap for the "real WYSIWYG editor" effort and a self-contained handoff for any agent continuing the work._

## Vision (locked decisions)

MarkRust becomes a **true WYSIWYG markdown editor**: the user edits a rendered rich document (bold is bold, no `**` visible); Markdown is the on-disk serialization format. Additionally: a **pure source** mode (the existing Typora-style delimiter-masking editor) and a **side-by-side** mode. All native Rust on **GPUI**, fast.

- v1 scope: core rich text + tables (cell editing, row/col ops) + inline images + frontmatter panel. Mermaid WYSIWYG is future (renders as inert code block; extension point kept).
- Save flow: **block-preserving by default** (untouched blocks keep exact original bytes). A diff dialog (Keep original / Normalize / Cancel) appears only when formatting beyond the user's edits would change — with the source-primary architecture that means only on an explicit Normalize action.
- Reuse: MIT/BSD sources fine with attribution (see `THIRD-PARTY-NOTICES.md`); no GPL. References cloned at `~/Projects/github_sources/{tui.editor,nimbalyst}`.

## Architecture: source-primary, tree-projected (the key decision)

**The rope buffer stays the single source of truth.** A derived `RichTree` (in `markrust-core::rich`) is authoritative for interpretation and command targeting. Every rich command compiles down to byte splices on the source, produced by re-serializing only the touched top-level block(s). Consequences:

- Block-preserving save is free: untouched blocks are untouched bytes. Default save writes the buffer verbatim.
- Undo stays byte-based (`UndoStack`/`EditOperation` keep working for both modes).
- Caret/selection stay source byte offsets; `RichEngine` provides delimiter-skipping snap/step and source↔visible mapping. Quote markers (`>`), list markers (`- ` / `1. ` / task), and inline chrome (`[` / `](url)` / `[ref]`, `**` / ticks, autolink `<>`) are not caret homes: Home/click/Left/Right skip them like fence prefixes (`clamp_raw_prefix` plus descendant `inline_ranges` on quote/list containers; `skip_inline_delimiter_chrome` for inline dest/marks). Empty `> ` / `- ` lines are still caret homes after the prefix (`empty_prefix_homes`) so typing is `> x` / `- x`. InsertText at that home on `>` (and quoted empty lists `>-` / `> -` / `>*`) without the marker space inserts the space (`> x`, not `>x`). Unquoted `-` / `*` do not auto-space (input rules for `---` / italic). Nested quotes skip every `>` onto body text. Wrapped list continuation indent is skipped the same way. A markdown soft wrap (`hello\nworld`) and a hard break (`a  \nb`) paint a space / newline whose click/IME map onto the break bytes (`SoftBreak` / `HardBreak` `source_range`), not the paragraph start. YAML frontmatter is not a body caret home (`frontmatter_body_start`: Comrak sourcepos is often `0..0`, so the captured fence `raw` length is the body start). Body commands (InsertText, Backspace, …) clamp out of the fences; `SetFrontmatter` / `SetFrontmatterField` still edit the panel. Leading newlines, the blank between top-level blocks (a standard `\n\n` separator, plus extras), and a trailing blank after the last block (`hello\n\n`) with no Comrak empty-paragraph node stay valid caret homes (`blank_caret_gaps`) so a click in the gap does not snap onto the next heading or back into the last paragraph, and Enter-at-start of a heading does not snap onto `# Title`. A click in leftover viewport below the last painted line uses the same trailing-blank home (and opens one when the file has none, so the next insert is a new paragraph) instead of a no-op. Click on the last line of the last block still sits in that paragraph. A document that is only newlines still hosts a caret. A single trailing `\n` is the last block's terminator, not a painted line.
- Fidelity layering: untouched blocks byte-exact automatically; touched blocks keep delimiter fidelity via captured attrs (`*` vs `_`, list markers, ATX/setext, fence char/len, break style) and `raw` slices on inline runs; explicit Normalize ignores fidelity.
- Source-mode masking is a **projection of the same comrak AST**, not a second Markdown parser. tree-sitter-md is gone. Masking + `spans.rs` stay as the source-mode renderer; they are not the WYSIWYG primary.

### Proven invariants (enforced by tests — keep them green)

- **Preserve identity**: `serialize(import(x), Preserve) == x` byte-exact for **all 649** CommonMark spec examples + all corpus cases (`crates/markrust-core/tests/rich_roundtrip.rs`).
- **Normalize fixed point**: `n(x) == n(n(x))` in one step.
- **Meaning preservation**: `html(x) == html(n(x))` under the comrak-HTML oracle.
- 26 documented Normalize-only skips (nested same-mark emphasis — inherent to flat inline runs, Lexical shares it; comrak multi-line inline-HTML literal quirks; link-in-image-alt). Preserve identity still holds for every skip.
- Byte-exact save round-trip e2e (`task_table_fence_frontmatter_survive_save_roundtrip`) still passes.
- Source spans share kinds with the rich tree on `showcase.md` (`source_spans_share_comrak_grammar_with_rich_tree`).
- Dirty-tab disjoint external edits merge (`dirty_tab_merges_disjoint_external_edits`).
- Load+parse of a 256 KiB mixed GFM fixture stays under 2.5s (`large_document_load_and_parse_stays_under_budget`); source layout of a 64 KiB fixture under 2.5s (`large_document_layout_stays_under_budget`). `cargo bench -p markrust-core --bench parse` and `cargo bench -p markrust-editor --bench layout` for local criterion numbers.

## P5–P9 design notes (for the next agent)

Shipped this pass (keep previous bullets; this pass added):
- **Empty highlight / strike unwrap:** Backspace or Delete that removes the last inner character of `==highlight==` or GFM `~~strikethrough~~` unwraps the empty marks (same as emptying `**bold**` → no leftover `****`). Previously `extend_empty_mark_wrappers` walked `*` / `_` / ticks / `~` but not `=`, so `==m==` + Backspace left `====` (empty `====` is not a highlight pair and painted as chrome). Delete unwrap now shares `expand_mark_delimiters` with caret chrome (`=` / `~~` / `^` included). Delete-forward from the inner character matches. Empty-caret Cmd-B still inserts `****` with the caret inside (insert, not leftover). Dest chrome on `[label](url)`, email autolink `<>`, and linked-image wrap dest are unchanged.
- **Link / mark chrome caret:** `[` / `](url)` / `[ref]` / `**` / ticks / autolink `<>` around a visible run are not caret homes (`clamp_raw_prefix` via `skip_inline_delimiter_chrome`). Left at the start of `[label](url)` lands on the previous visible character, not `[`. Backspace there deletes that character (the space), not `[` (no `see label](url)`). Delete at the end of the label does not swallow `](url)` (`trim_inline_chrome`). Caret after the last label letter still inserts into the label. Copy of a fully selected reference label includes `[label][ref]`. Click on painted `label` / `**bold**` / `` `x` `` was already the inner byte. Email autolinks (`<user@example.com>`) skip `<>` the same way URL autolinks do even when comrak does not flag `autolink` (child text is the address without `mailto:`; the flag is left false so Normalize HTML stays spec-identical). Wrapping dest around a linked inline image (`[![alt](img)](url)`) is skipped like a label dest (Backspace at the image does not leave `![alt](img)](url)`). Option-Backspace at a label start uses the same `trim_inline_chrome` (does not eat `[`).
- **Definition lists (Enter / Backspace):** Enter at the end of a term places the caret on the following `: ` details opener (or inserts `\n: ` if none follows) instead of splicing extra blank paragraphs (`Term\n\n\n\n: details`). Backspace and Option-Backspace at the start of details strip the `: ` marker like a list item (details become a paragraph; they do not concatenate into `Termdetails`). Quoted deflists keep `>`. Empty heading Enter, list-start Backspace, wrap-immune math, and table Tab are unchanged.
- **Wrap inside math / inline code / wiki / emoji:** Cmd/Ctrl+B/I/E/K with the caret (or a selection wholly inside the span) no-op, same as fenced-code bodies. Empty Cmd-B was splicing `****` into `$x^2$` (`$****x^2$`). A caret on neighboring paragraph text still wraps.
- **Selection keys:** Shift-Up / Shift-Down / Shift-Home / Shift-End extend the selection (only Shift-Left/Right were bound). Cmd-Left / Cmd-Right are line Home/End on macOS. Cmd-Shift-Left / Cmd-Shift-Right select to the line bound. Page-Up / Page-Down move by a viewport of lines; Shift-Page-Up / Shift-Page-Down extend. Option-Left / Option-Right (Ctrl-Left / Ctrl-Right) move by word; Option-Shift / Ctrl-Shift extend. Cmd-Up / Cmd-Down (Ctrl-Home / Ctrl-End) jump to document start/end; Cmd-Shift-Up / Cmd-Shift-Down (Ctrl-Shift-Home / Ctrl-Shift-End) extend. Option-Backspace / Option-Delete (Ctrl-Backspace / Ctrl-Delete) delete to the previous word start / next word end (`prev_word_caret` / `next_word_caret`; bold `**` skipped as stops). Cmd-Backspace / Cmd-Delete delete to the current visual/source line start / end (not the document). A non-empty selection is deleted like Backspace. Word/line delete clamps to the table `cell_edit_range` (cannot eat `|`) and stays in a fence `code_body_range`. Option-Backspace at the first visible character of a heading, list item, or quoted paragraph matches grapheme Backspace: convert the heading to a paragraph, strip the list marker, or strip one `>` — it does not splice the previous block (`hello# Title`). At a normal paragraph start after a heading or list, `# ` / `- ` of the previous block are not eaten (joining the previous *paragraph* is still OK). At a paragraph (or heading/list/quote) end, Option-Delete does not eat the next block’s `# ` / `- ` / `>` (no-op at that boundary; joining the next *paragraph* is still OK). Option-Backspace at a GitHub alert (`> [!NOTE]`) does not splice the previous paragraph into the callout. Overlay drafts delete in the field, not the body. WYSIWYG `on_action` handles those plus SelectUp/Down/Home/End and PageUp/Down (source already did). Overlay drafts move by word and to draft start/end too; YAML Shift-Up/Down/Home/End still extend the inner line. Shift-Left/Right and body Home/End are unchanged. Option-Up/Down (paragraph) is still unbound.
- **Copy/Cut:** Cmd/Ctrl+C/X were unbound (clipboard empty). WYSIWYG Copy writes source markdown of the visible selection (Typora), not painted-only inner text: a fully selected bold/italic/code/link includes `**` / `*` / `` ` `` / `[…](url)`; a fully selected heading/list/quote includes `# ` / `- ` / `>`; a selected image is `![alt](url)` (a linked image includes wrapping dest). Partial selection inside a run stays inner text. An empty caret copies the current block (heading `# `, list item `- `, quote `>`, fence ticks, paragraph source, image `![…](url)`; a table cell is cell text without `|`). Cut deletes that same block (collapsed table Cut is a no-op so the row is not destroyed). Source mode copies selected source bytes. Overlay Copy/Cut of a non-empty inner selection copies/cuts the draft; an empty overlay caret copies the whole chip/caption/frontmatter draft (Cut stays a no-op). Paste is still `EntityInputHandler` (no separate `cmd-v`).
- **Images (click/keyboard besides leftover-below):** `![alt](url)` and HTML `<img>` are one caret step (Left/Right skip the markdown; snap leaves the interior). Backspace after / Delete before removes the whole image. Click selects the image source range (inline still opens alt). Leftover-below still does not treat a last-block image as empty viewport.

- **Multiline paste / InsertText:** InsertText with embedded newlines does not run `\n` through `escape_text` (which still encodes decoded `&#10;` on serialize so CommonMark `foo&#10;&#10;bar` stays one paragraph). Paste writes real source newlines; a lone `"\n"` is still Enter (`SplitBlock`); in a paragraph a single `\n` is a soft wrap and `\n\n` starts a new paragraph; later lines that look like ATX `# `, list markers, `> `, or fence ticks stay those GFM blocks (not escaped `\# title`). A **single-line** paste of a complete GFM block (`# Title`, `- world`, fence opener — no `\n`) at an empty paragraph, a paragraph line start, or after `\n\n` is inserted as markdown (not escaped `\# Title`); a typed `#` / `-` / `>` keystroke is still an input rule (heuristic: space after the marker, or length > 2). In a list item, pasted `- ` / `* ` / `1. ` / `- [ ] ` lines become sibling items even without a leading newline (`- hello` + `- world` is two items, not `- hello- world`; plain lines still take list continuation indent); paste into a heading keeps the heading on the first line; quotes re-prefix each new line (`>`) without doubling a pasted `>` of the same depth; fenced/HTML/code bodies insert literal newlines with the same container prefixes Enter uses (stay inside; a cell or fence body is not turned into a heading). Table cells still map newlines to `<br>` (no row-splitting `\n`; `# ` stays cell text). GPUI paste (`EntityInputHandler::paste` / `replace_text_in_range`, including macOS `insertText`) is already `InsertText` — no separate `cmd-v` binding.
- **Soft/hard break click:** A markdown wrap (`hello\nworld` paints `hello world`) maps the painted space onto the source newline, not the paragraph start (`h`). Quoted `> hello\n> world` and list `- hello\n  world` map that space onto the newline, not `>` / `-`. A hard break (`a  \nb` / `a\\\nb`) maps the painted newline onto the two-space / backslash marker (end of the previous run), not `a`. Unquoted 1:1 paragraphs, heading click, table cells, leftover-below, and quoted-wrap Right onto `w` are unchanged.
- **Cmd-K empty dest:** Wrap serializes `[hello]()` (not `[hello](<>)`). InsertText at a leftover `<>` dest replaces the brackets. Autolinks still edit in place inside `<https://…>`.
- **Table selection:** Drag-select and Backspace/Delete across `|` clamp to the current cell (or refuse separator-only ranges) so GFM pipes are not deleted and header cells do not merge. Cmd/Ctrl+B/I/E/K (ToggleMark/ToggleLink) use the same cell clamp, so a leaked or Cmd-A selection cannot wrap `**` / `*` / `` ` `` / `[…]()` around pipes or collapse columns. Heading / list / blockquote (`SetBlockType` / `ToggleList` / `ToggleBlockquote`) no-op when the caret or selection start is in a table (GFM cells are not headings or lists; rewriting would eat `|`). Typing `# ` / `- ` / `* ` / `1. ` / `> ` / fences in a cell stays cell text (Typora); those input rules do not convert the row. First Cmd-A in a table selects the cell’s editable text (Typora), including an empty collapsed cell; a second Cmd-A selects the document. Overlay Cmd-A still selects the draft. First-cell Shift-Tab is still a no-op.
- **Empty marker space:** InsertText on an empty `>` that has no trailing space inserts that space (`> x`, not `>x`). Quoted empty lists (`>-`, `> -`, `>*`) get the same. A typed space on `>` stays `> ` (not `>  `). Unquoted `-` / `*` do not auto-space (that would break `---` and `*hi*`; those still use the space input rule).
- **Frontmatter vs body:** Body caret/selection cannot sit in YAML. `frontmatter_body_start` uses Comrak `source_range` or, when that is empty, the captured fence `raw` length. InsertText at 0 on a `---` file lands after the closing fence (not `x---`). Backspace at that body start does not nibble YAML. `SetFrontmatter` / `SetFrontmatterField` still edit the panel. Nested task checkboxes toggle independently (re-resolve `NodeId` after a splice; the click handler already uses the painted item id).
- **Fenced-code keyboard:** Tab inserts indent in the fence body (not `IndentList`, including a fence nested in a list — after the `- ` / `>` prefix, not before). Enter / Shift-Enter insert a newline inside the fence (a `- ` / `> ` code line is not list/quote exit; a caret on the ticks does not split ```; quoted fences keep `>` on every new line). Shift-Tab strips one tab or two leading spaces of **body** indent inside `code_body_range` after the list/quote prefix (it does not strip the indent that keeps a nested fence inside `- `, and does not treat `- foo` as a list item). Backspace at the first body byte is a no-op (does not nibble opening ticks, `>`, or the previous paragraph); Backspace at the start of a later body line joins without eating `>`. Delete-forward at the end of a fence or HTML body is a no-op (does not nibble closing ticks or `>`); Delete in the middle still removes a grapheme. Deleting the last body character leaves an empty fence (`extend_empty_mark_wrappers` does not swallow ```). Quoted HTML blocks follow the same stay-inside / keep-`>` rules. Caret snap skips fence chrome; `Block::code_body_range` is the editable inner range. **Click / IME / arrows:** the painted fence or HTML body is not 1:1 with source when lines carry `>` or list indent — `code_body_source_map` maps a visible index onto source by skipping that prefix (`build_code_block_layout` / `build_html_block_layout` / `character_index_for_point`). Clicking the first painted HTML (or indented-code) body character does not land on `>`. Left/Right and Up/Down (`next_caret` / `prev_caret` / `vertical_caret` / Home) stay on editable body offsets; they do not walk prefix bytes or skip user content. Unquoted fences stay 1:1. Table click and leftover-below click are unchanged. **Quoted paragraphs and list items** are on that same clamp path (they are not raw blocks): click on the first painted character of `> hello` / `- hello` / `1. hello` / `- [x] done` / `- [ ] hello` is `h` / `d`, not `>` / `-` / `1`. Nested `> > hello` paints and clicks `h`; Left at that start leaves the innermost body (does not sit on `>`). Empty `> ` / `- ` / `1. ` / `- [ ] ` sit after the prefix so InsertText is `> x` / `- x`. Right at a wrap inside a quote skips the next line’s `>` onto content; Right at the end of `- hello` / `  world` skips continuation indent onto `w`. Home/snap on quote and list containers uses descendant body ranges plus `empty_prefix_homes` for empty chrome-only lines. HTML-block tag bytes (`<div>`) skip on the same helper. Unquoted paragraphs stay 1:1; heading click and table cells are unchanged.
- **Leftover viewport click:** A click in the empty area below the last painted block (and any trailing blank-gap leaf) places the caret on the trailing blank if one exists (`hello\n\n`). If there is none (`hello`), leftover click inserts a trailing `\n\n` so the caret sits on a new empty paragraph — typing `x` is two paragraphs, not `hellox`. Click **on** the last line of the last block still sits in that paragraph. Clicks on a last-block image or thematic rule are not leftover (the image is selected; inline still opens alt). It is not a no-op and does not hit-test onto the last paragraph (which would insert mid-line). A document that is only newlines (no Comrak blocks) still paints a caret home so the user can type. One `\n\n` between blocks is still one visual empty line; a lone terminator `\n` is not painted.
- **Trailing blank after the last block:** If the file ends with a blank line (`hello\n\n` or extra newlines after the last terminator), WYSIWYG paints one clickable empty line after the last block. Click stays on that gap (does not snap into the last paragraph); typing appends a new paragraph. A single trailing `\n` is only the block terminator and is not painted. One `\n\n` between two blocks is still one visual empty line (not doubled). Extra unused newlines stay one Down step.
- **Empty heading Enter / heading-start Enter / heading-start Backspace:** Enter on an empty ATX heading (`# ` … `###### `) converts it to a paragraph (quoted: `> `). Enter at the start of a **non-empty** heading inserts a blank paragraph above and keeps the heading (ATX 1–6 and setext; quoted headings keep `>`). In a list item (`- # Title`) that Enter inserts a blank list item above (not a document-level blank). Comrak has no empty-paragraph node, so a document-level blank is leading/separator newlines; `snap_caret` / `block_at` leave those offsets in place (they do not jump onto `# Title`), WYSIWYG paints a clickable empty line for a standard `\n\n` as well as extra blanks, and arrow-up from the heading can sit on that blank. Enter mid/end on a non-empty heading still splits like a paragraph. Backspace at the first visible heading character strips `#` or the setext underline (quoted headings keep `>`). In a list item (`- # Title`) that Backspace strips the heading first (`- Title`); a second Backspace strips the list marker. Mid-heading Backspace still deletes a grapheme. Empty CommonMark setext is not a heading (thematic break); non-empty setext start-Backspace is covered.
- **Cmd-K URL caret:** Cmd/Ctrl+K on a selection (or a word under the caret) wraps with empty `()` (not `<>`) and leaves the caret in the destination, like Typora / source wrap. Typing fills the URL (`[hello](https://e.com)`, not `[hello](https://e.com<>)`). If the dest is already `<>`, InsertText at that caret replaces `<>`. Whitespace still inserts `[]()` with the caret in the label. Autolink in-place edits keep `<https://…>`.
- **Empty-caret wrap:** WYSIWYG Cmd/Ctrl+B/I/E with no selection inserts `****` / `**` / `` ` ` `` and leaves the caret between the marks (second press unwraps). Typing then yields `**x**` / `*x*` / `` `x` ``. Previously the whole run under the caret was toggled. Cmd/Ctrl+K on whitespace still inserts `[]()`; on a word it still wraps that word. Fenced-code bodies ignore wrap. ## Dev workflow — hard-won gotchas

- **Build env**: `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` — `xcode-select` points at CommandLineTools, which lacks the Metal shader compiler (`xcrun: unable to find utility "metal"`).
- **Always `cargo build --workspace`** before running `target/debug/markrust`: building `-p markrust-app` rebuilds only the lib — the `markrust` bin package stays stale (this burned a debugging hour).
- **gpui font-kit**: `gpui_platform` must keep `features = ["font-kit"]` or macOS gets a silent `NoopTextSystem` and renders no text at all.
- **gpui run invariants**: `TextRun`s passed to `shape_line`/`StyledText::with_runs` must exactly tile the text on char boundaries; tree-sitter *code* highlight spans nest/overlap and must be sanitized first (see `wysiwyg/blocks.rs::code_runs` and `source/element.rs::build_runs_for_line`).
- **Visual verification**: run the app, `screencapture -x out.png` (needs sandbox disabled → permission prompt), read the PNG. Launching the app steals focus — batch checks and kill instances promptly; every panic-abort also spawns a macOS crash dialog for the user.
- **Panic analysis**: panics append structured reports (message, location, full backtrace) to `~/Library/Logs/MarkRust/panics.log` via `markrust_app::crash::install_panic_logger()`. Check that file first when the app dies; it is written before the crash dialog appears.
- `cargo test/build` piped to `grep`/`tail` masks exit codes — check `pipestatus` or run unpiped.
